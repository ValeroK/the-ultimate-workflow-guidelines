# Follow-ups after 4.8.0

Input for the next plan (make the gates and the unattended run simpler). Written 2026-11-13. Not a plan a run can start.

## New plugin faults found while building 4.8.0

17. The run-start preflight reads every backticked file name in a plan as a path from the repo root, so short names such as report.md park every card as missing input.
18. The stop gate (G3) blocks a session for edits another session makes in the same checkout, and the only way out it offers (verify.js) writes state that the other session's run reads.
19. An agent given a plugin root that is another checkout of the same repo edits it: the run wrote the plan-subfolder code into the frozen snapshot.
20. prepare --range A..B lists the changed files from the working tree, not from the range (the saved diff is right).
21. The gates are too complicated for daily use (owner, 2026-11-12): fewer gates, none that can block a session for another session's work or ask for something it cannot do, no unattended run on the plugin's own code.
22. The context pack budget was not held: about 37,000 tokens per card against 15,000, nothing dropped.

## Concerns from the whole-branch review of 2026-11-12 (below the confidence bar)

Security first, then in the order the review gave.

1. **security** (.cursor-plugin/ultimate-workflow/lib/run-rules.js:42): narrowedExperts treats any card not named findings*/fixup* as a confirmed plan card. cardCommit (autopilot.js:740-760) never checks confirmed_hash. So an agent with a shell in the run could add a card such as `x` with `experts: none` and `paths: **`, run `card-commit --card x`, and G6 would ask for no experts. Before this change, G6 asked for the union of the covering cards. Why it is not a finding: Rated 6. It needs an agent in the loop that already holds a shell and write access to the plan. Such an agent could already narrow G6 before this change by editing a card's experts field. The run script itself only commits card names taken from the plan, so I found no new outsider-controlled path.
2. **security** (.cursor-plugin/ultimate-workflow/hooks/lib/state.js:122): pointerName takes realpathSync of both the root and the target, and refuses when path.relative starts with '..' or is absolute. A plan file whose own name begins with '..' (for example '..PLAN-x.md' inside the root) would be refused wrongly. Why it is not a finding: It fails closed, not open, so it is not a security defect. At most it is a correctness detail for the developer, and isPlanName already requires the base name to start with PLAN-.
3. **developer** (.cursor-plugin/ultimate-workflow/experts/autopilot.js:882): In harvestBranch, the freeName taken() check uses git with allowFail and tests status === 0, so a git error counts as 'free'. That goes against the architect's constraint and freeName's own doc that a git error counts as taken. Why it is not a finding: No wrong outcome I can show: the later `git branch <name> <tip>` has no -f, so it refuses to overwrite an existing branch and throws, and run() reports that as ok:false.
4. **developer** (.cursor-plugin/ultimate-workflow/phases/run.js:1133): The plan line 'the report names which run each fix-up card came from' is honoured only indirectly. Fix-up cards from earlier runs appear in 'Before this run' via `earlier`. No entry names the run that added a fix-up card. Why it is not a finding: Each report is per run, so a reader can infer it. I could not show that a user is misled, so I rate it below 8.
5. **developer** (.cursor-plugin/ultimate-workflow/phases/run.js:484): If the recheck agent returns null twice, the card goes on with recheck: false and the failure is not added to `failed`, unlike the expert and refute retries next to it. Why it is not a finding: This is the same as before the change, and the plan asked only for one retry for recheck. I did not trace whether the commit gate refuses a lane with recheck: false.
6. **quality** (evals/experts/claims.test.js:226): The check that the tests phase (claimsOf in phases/tests.js) and lib/claims.js agree on whether a measure: line is understood only covers five sample lines. None of them has a drive prefix, a backslash or an absolute glob, so the two parsers could drift on those forms without a test noticing. Why it is not a finding: I could not show such a drift: both parsers seem to refuse those forms today (the phase's character class has no colon or backslash). Confidence is about 5.
7. **quality** (evals/experts/run-phase.test.js:1): run-phase test 34 checks the fix-up lane against narrowedExperts using a hand-built card list and a stand-in covers() (startsWith after stripping '**'), not the plan text card-add wrote or the real cards.covers. Why it is not a finding: autopilot-fixes gate-card 13/14 run the real commitEvidence on the real plan for the same shared-file case. So a wrong implementation would have to pass both tests, and I could not construct one. Confidence is about 4.
8. **softarch** (.cursor-plugin/ultimate-workflow/experts/autopilot.js:825): Harvest branch free names (`uw/harvest/<feature>-N`) and the runState openHarvests regex share a namespace with features whose own names end in -N. A second harvest of feature `x` takes `uw/harvest/x-2`, which is the base name of feature `x-2`'s harvest, and each feature then counts the other's branch as its own open harvest. Why it is not a finding: It needs two features in one repository whose names differ only by a -N suffix. FEATURE allows such names, but I found no such pair in practice. Confidence 6.
9. **softarch** (.cursor-plugin/ultimate-workflow/lib/run-rules.js:15): The card-list boundary still has three readers rather than the one definition the plan asked for: cardsRange in cards.js, its own state machine in confirmHash, and acceptedFiles in run-rules.js, which scans the whole plan text with a copied item regex. They agree today, but cardsRange takes the first `Cards` heading while confirmHash treats every heading named `cards`, at any level, as the section. Why it is not a finding: I found no plan in the repository with a second Cards heading, and none with a card bullet outside the Cards section that holds an `accepted:` line, so I could not show a divergence on any real input. Confidence 6.
10. **softarch** (.cursor-plugin/ultimate-workflow/experts/cards.js:84): cards.parseCards does not know the new `accepted:` run field and puts any unknown field into `carried`. Once `--resume --accept` writes `accepted:` as the plan intends, the accepted file paths would reach the builder as carried work and would enter reusableCard's comparison. Why it is not a finding: Nothing in the diff writes `accepted:` yet (the plan's carried quality item says so too), so the path cannot be reached today. Confidence 5.
11. **genai** (.cursor-plugin/ultimate-workflow/phases/run.js:undefined): If refute returns a valid result that leaves out some finding indices, those findings are kept as 'unverified' and a high-confidence one can still drive the paid fix round. Why it is not a finding: This is older code that the diff does not touch or make easier to reach. The new rule is only about a null refute, so this is not a finding against this change.
12. **architect** (.cursor-plugin/ultimate-workflow/phases/run.js:1040): If `stoppedBecause` is set while fix-up group 1 runs, the loop breaks. Groups 2..4 then get no card, yet the review is still recorded as done (reviewedHead moves). Their confirmed high and medium findings are never written to run.json the way pendingFindings is, so a settling resume reviews only reviewedHead..HEAD and never brings them back. The report that lists them is rewritten on the next run. Why it is not a finding: It needs a stop during the fix-up loop. The findings may also survive as catches in the ledger, which I did not trace. Confidence 6.
13. **architect** (.cursor-plugin/ultimate-workflow/experts/autopilot.js:881): A harvest whose `harvest-branch` step created uw/harvest/<f> before the run died ahead of `settle:record` is run again on the next resume and makes uw/harvest/<f>-2. The only guard against duplicate proposals is the harvester prompt's instruction to drop what the open branches already hold, which a model can ignore. Why it is not a finding: The window is a few steps long, and the plan accepted the prompt-based mitigation for the duplicate-proposal risk I raised at planning. Confidence 5.
14. **devops** (.cursor-plugin/ultimate-workflow/hooks/lib/state.js:undefined): The plan-subfolder change makes the hooks read internal/plans/ plans once a pointer is set. A run of this plan in this repository can then be judged by the new state.js partway through, and the plan never says from which card on that applies. Why it is not a finding: This is a sequencing risk in how the run uses the repository, not a defect in the diff. Whether it bit depends on how the run was driven, which I cannot see. Confidence about 4.
15. **devops** (CHANGELOG.md:undefined): After the budget raise, the only size guard on what ships is release-skills.yml's 2 MB ZIP ceiling, and that check runs only at tag time. Growth from the two new lib/ files is first seen at release. Why it is not a finding: This was already the case: the budget raise is part of 4.8.0, not this diff, and the plan accepted the trade-off (deviation 3). I have no failure path from this diff. Confidence about 3.

## Lessons from the five harvest branches (read 2026-11-13, branches then deleted)

The five branches (uw/harvest/memory-index-1 to -4, uw/harvest/run-fixes) proposed mostly the same lessons, because harvest ran on every resume. What is worth keeping for the simplification plan:

- Commit gate G6 worked out the experts from the changed files, not the card, so cards sharing a file had to share an experts line. Fixed in 4.8.0 for run commits; hand commits still take the union. One rule for both would be simpler.
- With several plans and no pointer, the gates guessed the plan by modification time. A guess is a source of surprise; one explicit active plan is simpler.
- The experts/ byte budget parked a whole run on working code. Size limits that stop a run should be checked at plan time, or be warnings.
- The preflight treats every backticked document name as a path (fault 17).
- Agent text inside q() on a command line is a shell injection risk; fixed by files in 4.8.0. A single "pass text as a file" helper would remove the class.
- The memory check sits inside the commit gate, ahead of G6, and blocks only what the commit adds. Another check in the same gate; a candidate to fold or drop.
- An expert that returns nothing is retried once (4.8.0).
