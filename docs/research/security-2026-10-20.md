Extra facts from the same pages:

- `actions/checkout` keeps its token in `.git/config` for the job unless `persist-credentials: false`.
- After a workflow is onboarded to `actions.lock`, allowed-actions policies check the locked SHA, so tag entries such as `actions/checkout@v6` stop matching.
- Onboarded workflows rewrite in-repository `uses: ./...` to `uses: $/...`, which needs no lockfile entry.
- Repositories created, renamed or transferred after 2026-07-15 get the immutable `sub` form with numeric owner and repository ids; not on GitHub Enterprise Server.
- Do not gate `iam:PassRole` with `iam:ResourceTag` or `aws:ResourceTag`: AWS says it is unreliable. Use a role-name prefix in the resource instead.
- `iam:PassRole` passes a role only to a service in the same account.
- RFC 8725: each key is used with exactly one algorithm, checked at use; both layers of a nested JWT are validated with the application's keys and algorithms.
- MCP proxies: reject a callback whose `state` is missing or does not match, and never treat possession of a state handle as authentication.
- MCP clients validate URLs from servers, reject shell-interpretable characters, and do not follow redirects to internal resources.

## Our assessment of the reply

- **The three claims we doubted all hold** on GitHub's own pages: `allow-unsafe-pr-checkout`, `actions.lock`, and the 2026-11-02 default policy. They are recent and specific, so each row that uses them carries the date.
- **The checkout guard changes what a `pull_request_target` finding looks like.** Since `actions/checkout` refuses a fork head without `allow-unsafe-pr-checkout: true`, the path now runs through that input, `git fetch`, `gh pr checkout` or a downloaded artifact. `review.md`'s worked finding is updated to match.
- **Item 10 stays a lead, not a rule:** only secondary pages state the newline injection. A finding still needs the path from the untrusted value to the later step that uses it.
- **The Copilot `sub` bug** is a community report acknowledged by GitHub staff, not documentation; it is recorded, not put in a reference.
- Some exceptions are not exceptions (item 18's "administrative roles", item 2's settings). Not carried over.
